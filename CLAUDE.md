# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Microverse In Box (盒中小世界) is a god-simulation sandbox game built on Godot 4.3+. It's a multi-agent AI social simulation system where AI characters possess independent thinking, memory, and can autonomously interact, form relationships, and complete tasks. This is an open-source demo version; the full version will be released on Steam.

**Key Concept**: Similar to Stanford AI Town, AI characters live autonomously in an open world, powered by large language models (LLM) from various providers (OpenAI, Claude, Gemini, DeepSeek, Doubao, Kimi, Ollama).

## Architecture Overview

### Singleton Managers (Autoloaded)
The game uses Godot's autoload system for global managers (see [project.godot:18-26](project.godot#L18-L26)):

1. **SettingsManager** ([script/ui/SettingsManager.gd](script/ui/SettingsManager.gd))
   - Manages all game settings including API configurations
   - Stores per-character AI settings (each character can use different AI providers/models)
   - Uses signal-based architecture: emits `settings_changed` signal when settings update
   - Persists to `user://settings.cfg` and `user://character_ai_settings.cfg`

2. **DialogManager** ([script/ai/DialogManager.gd](script/ai/DialogManager.gd))
   - Central hub for conversation coordination
   - Delegates to DialogService for multi-conversation handling
   - Provides company context (employee info, product details) to AI prompts
   - Handles keyboard input: T to start dialog, L to end dialog

3. **APIManager** ([script/ai/APIManager.gd](script/ai/APIManager.gd))
   - Creates HTTPRequest nodes for AI API calls
   - Fetches per-character AI settings from SettingsManager
   - Uses APIConfig for provider-specific request formatting
   - Auto-cleanup: HTTPRequest nodes self-destruct after completion

4. **CharacterManager** ([script/CharacterManager.gd](script/CharacterManager.gd))
   - Tracks currently selected character
   - Handles mouse click selection and character switching
   - Syncs camera following and GodUI (god mode UI) with current selection
   - Detects nearby characters for dialog initiation (DIALOG_DISTANCE = 100.0)

5. **MemoryManager** ([script/ai/memory/MemoryManager.gd](script/ai/memory/MemoryManager.gd))
   - Manages character memories with importance levels and types
   - Stores memories in character metadata: `character.get_meta("character_data")`
   - Auto-cleanup: keeps max 50 memories, prioritized by importance and recency
   - Provides formatted memory strings for AI prompts

6. **GameSaveManager** ([script/GameSaveManager.gd](script/GameSaveManager.gd))
   - Handles save/load game state
   - Keyboard: F1 to toggle save/load UI

### API Configuration System

**APIConfig** ([script/ai/APIConfig.gd](script/ai/APIConfig.gd)) is a static configuration class that centralizes all AI provider logic:

- **Supported Providers**: Ollama, OpenAI, DeepSeek, Doubao (ByteDance), Gemini, Claude, KIMI (Moonshot), OpenAI-Compatible
- **Request Formats**: Maps providers to format types (`ollama`, `openai`, `gemini`, `claude`)
- **Response Parsing**: Unified `parse_response()` handles different API response structures
- **Dynamic Headers**: Builds provider-specific headers with API key substitution

**Key Methods**:
- `get_api_types()`: Returns all available provider names
- `build_request_data(api_type, model, prompt)`: Creates provider-specific request body
- `build_headers(api_type, api_key)`: Generates headers with authentication
- `parse_response(api_type, response, character_name)`: Extracts text from API responses

### Character AI System

**AIAgent** ([script/ai/AIAgent.gd](script/ai/AIAgent.gd)) - Note: This file is very large (31k+ tokens), read specific sections as needed:
- Attached to each character scene (see [scene/characters/](scene/characters/))
- Manages character autonomous behavior: idle, conversation, task execution
- Builds AI prompts by combining: personality + memories + conversation history + current context
- Handles API responses and updates character state/memories
- Uses metadata storage pattern: `character.set_meta("character_data", {...})`

**CharacterPersonality** ([script/CharacterPersonality.gd](script/CharacterPersonality.gd)):
- Defines 8 unique character personalities (Stephen, Tom, Lea, Alice, Grace, Jack, Joe, Monica)
- Each character has: position, personality traits, speaking style, work duties, work habits
- Personalities are humorous and exaggerated (e.g., Stephen is a PUA-style boss, Joe is a toxic tester)

### Data Flow: How a Conversation Works

1. **User initiates**: Presses T key → DialogManager detects input
2. **Character selection**: DialogManager gets current character from CharacterManager
3. **Nearby detection**: Finds characters within DIALOG_DISTANCE
4. **Conversation start**: DialogService creates conversation instance, emits `conversation_started`
5. **Prompt building**: AIAgent constructs prompt with:
   - Character personality (from CharacterPersonality)
   - Recent memories (from MemoryManager, max 3)
   - Company context (from DialogManager)
   - Current emotional state (from character metadata)
6. **API call**: APIManager creates HTTPRequest with character-specific AI settings
7. **Response processing**: APIConfig parses provider-specific response format
8. **Memory update**: MemoryManager adds conversation memories with timestamps
9. **UI update**: DialogBubble shows conversation text above characters
10. **State update**: Character metadata updated with new memories/emotional states

### Memory System Details

Memories are stored in character metadata with this structure:
```gdscript
{
  "content": "Memory text",
  "timestamp": "2025-01-15 14:30",  # Human-readable
  "type": MemoryType (PERSONAL/INTERACTION/TASK/EMOTION/EVENT),
  "importance": MemoryImportance (LOW/NORMAL/HIGH/CRITICAL),
  "created_at": 1736932200.0  # Unix timestamp for sorting
}
```

### Important Design Patterns

1. **Signal-Based Decoupling**: Managers communicate via signals, not direct calls
   - Example: SettingsManager emits `settings_changed`, APIManager listens

2. **Metadata Storage**: Character state stored in node metadata, not separate data structures
   - Access: `character.get_meta("character_data", {})`, `character.set_meta("character_data", data)`

3. **Per-Character AI Settings**: Each character can use different AI providers/models
   - Check: `SettingsManager.has_character_ai_settings(character_name)`
   - Get: `SettingsManager.get_character_ai_settings(character_name)`

4. **Autoload Singletons**: Use `get_node("/root/ManagerName")` to access managers
   - Example: `var dialog_manager = get_node("/root/DialogManager")`

## Common Development Tasks

### Adding a New AI Provider

1. Update [APIConfig.gd:44-145](script/ai/APIConfig.gd#L44-L145) in `_initialize()`:
   ```gdscript
   _providers["NewProvider"] = APIProvider.new(
       "NewProvider",
       "Display Name",
       "https://api.example.com/v1/chat",
       ["model1", "model2"],  # Available models
       true,  # Requires API key
       {"Content-Type": "application/json", "Authorization": "Bearer {api_key}"},
       "openai",  # Request format (reuse existing or add new)
       "openai"   # Response parser
   )
   ```

2. If using a new request format, add case in `build_request_data()` at [APIConfig.gd:173-210](script/ai/APIConfig.gd#L173-L210)

3. If response format differs, add case in `parse_response()` at [APIConfig.gd:242-282](script/ai/APIConfig.gd#L242-L282)

### Adding a New Character

1. Create character scene in [scene/characters/](scene/characters/) (duplicate existing character)
2. Add personality to [CharacterPersonality.gd:6-63](script/CharacterPersonality.gd#L6-L63) PERSONALITY_CONFIG
3. Add character to office scene: [scene/maps/Office.tscn](scene/maps/Office.tscn)
4. Update DialogManager's employee info in `get_company_employees_info()` (auto-generated from CharacterPersonality)

### Modifying AI Prompt Context

Key locations for prompt construction:
- Company info: [DialogManager.gd:44-50](script/ai/DialogManager.gd#L44-L50) `get_company_basic_info()`
- Employee list: [DialogManager.gd:32-41](script/ai/DialogManager.gd#L32-L41) `get_company_employees_info()`
- Character status: [DialogManager.gd:53-86](script/ai/DialogManager.gd#L53-L86) `get_character_status_info()`

### Working with Character Metadata

Character state is stored in metadata, not class properties. Always use this pattern:
```gdscript
# Read
var character_data = character.get_meta("character_data", {})
var memories = character_data.get("memories", [])

# Write
character_data["memories"] = new_memories
character.set_meta("character_data", character_data)
```

Key metadata fields:
- `memories`: Array of memory dictionaries
- `money`: Integer, character's money
- `mood`: String, current mood
- `health`: String, health status
- `relations`: Dictionary, relationships with other characters

## Map System

The map system provides the visual environment and interaction framework for AI characters. It includes lighting, buildings, and optimization systems.

### Map Scripts

Located in [script/world/](script/world/):

1. **DayNightCycle** ([script/world/DayNightCycle.gd](script/world/DayNightCycle.gd))
   - Extends CanvasModulate to control global lighting color
   - 7 time periods: dawn, morning, noon, afternoon, dusk, evening, night
   - Connects to TimeSystem's `hour_changed` signal
   - Emits `night_time_start` (19:00) and `day_time_start` (6:00) signals
   - Smooth color transitions with configurable duration
   - Customizable color presets via @export variables

2. **WindowLights** ([script/world/WindowLights.gd](script/world/WindowLights.gd))
   - Manages building window lights (Light2D nodes)
   - Auto-collects lights from "window_lights" group
   - Turns lights on/off based on DayNightCycle signals
   - Random delays for realistic effect (0-2 seconds)
   - Fade in/out animations (0.5 seconds)

3. **StreetLights** ([script/world/StreetLights.gd](script/world/StreetLights.gd))
   - Manages street lamp system
   - Collects lights from "street_lights" group
   - Optional procedural generation along paths
   - Flicker effect for realism (configurable interval and intensity)
   - Supports StreetLight scene instances

4. **StreetLight** ([script/world/StreetLight.gd](script/world/StreetLight.gd))
   - Individual street lamp node (extends Node2D)
   - Methods: `turn_on()`, `turn_off()`, `toggle()`
   - Optional flicker animation
   - Configurable light color, range, and energy
   - Scene: [scene/world/StreetLight.tscn](scene/world/StreetLight.tscn)

5. **InteractionZone** ([script/world/InteractionZone.gd](script/world/InteractionZone.gd))
   - Base class for interactive areas (extends Area2D)
   - Types: enter (buildings), work, sit, talk, rest, custom
   - Detects AI characters entering/exiting
   - Emits `interaction_triggered(zone_name, character)` signal
   - Optional highlight on mouse hover
   - Cooldown system to prevent rapid re-triggers
   - Character restriction (allow only specific characters)

6. **Building** ([script/world/Building.gd](script/world/Building.gd))
   - Base class for all buildings (extends StaticBody2D)
   - Types: house, office, cafe, bar, shop, public
   - Manages entrance interaction zone
   - Access control: owner check, relationship requirements, time restrictions
   - Window lights integration
   - Tracks characters inside building
   - Methods: `can_character_enter()`, `enter_building()`, `exit_building()`

7. **ViewportCulling** ([script/world/ViewportCulling.gd](script/world/ViewportCulling.gd))
   - Performance optimization system
   - Hides objects outside camera view
   - Configurable buffer zone (default 5 tiles)
   - Groups: trees, decorations, buildings, characters, effects
   - Optional process disabling for hidden objects
   - Performance stats tracking

### CameraController

Extended [CameraController](script/CameraController.gd) (class_name: CameraController):

**Features**:
- Follow mode: Smoothly follows selected character
- Manual mode: Right-click or middle-click drag to pan
- Zoom levels: 5 presets (0.5x, 0.75x, 1.0x, 1.5x, 2.0x)
- Map bounds: Restricts camera to map area
- Keyboard shortcuts:
  - `Space`: Restore view to current character
  - `R`: Reset camera to initial state
  - `F`: Toggle follow mode on/off

**Key Methods**:
- `follow_character(character)`: Start following a character
- `reset_camera()`: Return to initial position and zoom
- `toggle_follow_mode()`: Switch between follow and free modes
- `zoom_in()` / `zoom_out()`: Step through zoom presets
- `get_visible_rect()`: Returns current visible area (for culling)

### Map System Integration

**With TimeSystem**:
- DayNightCycle listens to `hour_changed` signal
- Updates lighting every hour
- Triggers day/night events at specific hours

**With Characters**:
- InteractionZone detects characters via `is_in_group("characters")`
- Building checks character metadata for access control
- CameraController follows character via `target` property

**With Lighting**:
```
TimeSystem (hour=19)
  → DayNightCycle.night_time_start
  → WindowLights.turn_on_all_lights()
  → StreetLights.turn_on_all_lights()
```

### Office Map System Integration

**OfficeMapSetup** ([script/world/OfficeMapSetup.gd](script/world/OfficeMapSetup.gd)) provides one-click integration of map systems into the Office scene.

**Quick Start**:
1. Open [scene/maps/Office.tscn](scene/maps/Office.tscn) in Godot editor
2. Attach `OfficeMapSetup.gd` script to root "Office" node
3. Press F5 to run → All systems auto-initialize
4. Press Ctrl+S to save → Nodes persist to scene

**What It Creates**:
- **DayNightCycle** (CanvasModulate): Global lighting control (7 time periods)
- **WindowLights** (Node2D + 8 Light2D): Office window lights (auto on/off at 19:00/6:00)
- **OfficeAreaLights** (Node2D + 9 Light2D): Ceiling lights for work areas, meeting rooms, gym
- **InteractionZones** (Node2D + 11 Area2D): Work desks, meeting room, gym, tea room
- **Camera Bounds**: Configures MainCamera's `map_bounds` to (0, 0, 1200, 600)

**Export Variables**:
```gdscript
@export var auto_setup_on_ready: bool = true
@export var enable_day_night_cycle: bool = true
@export var enable_window_lights: bool = true
@export var enable_office_lights: bool = true
@export var enable_interaction_zones: bool = true
@export var configure_camera_bounds: bool = true
```

**Features**:
- Non-destructive: Does not modify original Office.tscn data (17052 lines preserved)
- Auto-detection: Skips creation if nodes already exist
- Editor-compatible: Sets node `owner` correctly for scene persistence
- Customizable: Toggle features via export variables

**Created Node Hierarchy**:

**Integration Points**:
- Connects to TimeSystem for hour-based lighting
- InteractionZones trigger character behaviors (work/talk/rest)
- Window lights respond to DayNightCycle signals
- Camera bounds prevent viewport from exceeding map area
