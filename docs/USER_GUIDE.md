## 🧠 核心概念

### 1. AI角色系统

苏格拉底终端通过8个预设AI角色实现多角度讨论:

| 角色 | 核心职责 | 发言特征 |
|------|---------|----------|
| **苏格拉底** | 提问引导 | "你认为...吗?" "如何定义..." |
| **批判者** | 挑战论点 | "这里有问题" "忽略了..." |
| **理论家** | 深入原理 | "数学上..." "形式化定义..." |
| **实践者** | 应用落地 | "实际中..." "工程上..." |
| **类比大师** | 具象化解释 | "就像..." "比如..." |
| **综合者** | 整合观点 | "从以上可见..." "共识是..." |
| **魔鬼代言人** | 唱反调 | "但如果..." "相反的观点..." |
| **学术派** | 引用来源 | "根据XX论文..." "历史上..." |

### 2. 深度检测机制

系统每5轮对话自动评估讨论深度:

**评估维度**:
- **概念层次** (0-4层): 表面现象 → 机制 → 原理 → 基础假设
- **批判互动** (次数): AI之间的质疑、纠正、补充
- **关键词深度** (分数): 检测"本质"、"原理"、"反例"等深度词汇

**分数计算**:
```
深度分数 = 关键词分数 * 0.4 + (概念层次/4) * 0.3 + (互动数/5) * 0.3
```

**合格标准**:
- 深度分数 ≥ 0.6
- 概念层次 ≥ 2层
- 批判互动 ≥ 3次

### 3. 对话流程

```
用户输入话题
    ↓
[首发] 苏格拉底(主持人)提问引导
    ↓
[轮流] 各AI按顺序发言
    ↓
[深度检测] 每5轮评估一次
    ├─ 深度不足 → 系统提示 + AI深入
    └─ 深度充分 → 询问用户是否理解
    ↓
用户说"懂了" → 主持人总结 → 讨论结束
```

## 📋 命令详解

### 核心命令

#### `/topic [主题]` - 开始新话题

启动新一轮讨论,会清空之前的对话历史。

**示例**:
```bash
/topic 什么是量子纠缠?
```

**效果**: 所有AI角色重新开始,围绕新话题展开讨论。

---

#### `/say [文本]` - 插话发言

在讨论进行中插入您的观点或疑问。

**示例**:
```bash
/say 我不太理解"纠缠态"是什么意思
```

**技巧**:
- 提出具体疑问,而非泛泛的"不懂"
- 指出您认为矛盾的地方
- 提供新的思考角度

---

#### `/stop` 或 `懂了` - 结束讨论

**停止方式**:
1. 输入 `/stop` 或 `/understood`
2. 直接说"懂了"、"明白了"、"清楚了"
3. 英文: "I understand", "got it"

**结束后**: 主持人AI会生成一份总结,包括:
- 核心概念
- 关键要点
- 常见误区
- 进一步延伸
- 生活类比(如适用)

### AI管理命令

#### `/agents list` - 查看角色列表

显示所有AI角色及其配置状态。

**输出示例**:
```
- 苏格拉底 [OpenAI/gpt-4o-mini] 启用 (主持)
- 批判者 [Claude/claude-3-5-sonnet-20241022] 启用
- 理论家 [OpenAI/gpt-4o-mini] 禁用 (未设置APIKey)
```

**状态说明**:
- **启用**: 该角色会参与讨论
- **禁用**: 未设置API Key或被手动禁用
- **(主持)**: 负责总结和引导

---

#### `/agents key [名称] [API密钥]` - 设置密钥

为AI角色配置API Key,设置后自动启用该角色。

**示例**:
```bash
# 直接设置
/agents key 苏格拉底 sk-proj-abc123...

# 使用环境变量
/agents key 批判者 ${ENV:ANTHROPIC_API_KEY}
```

**安全建议**: 推荐使用环境变量,避免密钥明文存储。

---

#### `/agents add [名称] [API类型] [模型]` - 添加新角色

创建自定义AI角色(最多10个)。

**示例**:
```bash
/agents add 哲学家 OpenAI gpt-4o
/agents add 数学家 Claude claude-3-opus-20240229
```

**可选API类型**:
- OpenAI
- Claude
- DeepSeek
- Gemini
- Doubao (豆包)
- KIMI
- Ollama (本地)
- OpenAI-Compatible (兼容接口)

---

#### `/agents color [名称] [颜色]` - 设置显示颜色

为角色指定终端显示颜色,方便区分发言。

**示例**:
```bash
/agents color 苏格拉底 #4A90E2
/agents color 批判者 #FF6B6B
```

**颜色格式**: 十六进制RGB,如 `#RRGGBB`

#### `/agents moderator [名称]` - 设置主持人

指定主持人角色(只能有一个),负责:
- 讨论引导
- 最终总结
- 首发提问

**示例**:
```bash
/agents moderator 苏格拉底
```

## 🎓 AI角色详解

### 苏格拉底 (主持人推荐)

**人格**: 谦逊的引导者,不直接给答案,而是通过精准提问让您自己思考出答案。

**擅长场景**:
- 概念定义 (什么是X?)
- 价值观讨论 (XX好吗?)
- 揭示假设 (我们是否默认了...?)

**发言示例**:
```
在回答"什么是递归"之前,我想先问:
你认为"自己调用自己"就是递归的全部吗?
这个定义在所有情况下都成立吗?
如果一个函数调用了另一个函数,而那个函数又调用了第一个,算递归吗?
```

**如何与之互动**:
- 认真回答他的问题
- 说出您的直觉,即使不确定
- 允许他挑战您的定义

---

### 批判者

**人格**: 建设性批评专家,专挑漏洞但目的是完善理解。

**擅长场景**:
- 检查论证逻辑
- 找反例和边界情况
- 识别隐含假设

**发言示例**:
```
等等,前面说的"递归必须有终止条件"不够准确。
反例:互递归可能没有单一的终止条件,而是两个函数相互制约。
更严格的说法应该是:递归调用链的某处必须存在停止递归的路径。
```

**如何与之互动**:
- 别把批评当攻击
- 思考他提的反例
- 问"那么正确的说法是什么?"

---

### 理论家

**人格**: 深度学术派,追求严格的数学定义和形式化推导。

**擅长场景**:
- 科学原理 (为什么E=mc²?)
- 数学证明
- 算法复杂度分析

**发言示例**:
```
递归的λ演算定义:
Y组合子 Y = λf.(λx.f(x x))(λx.f(x x))
这是一个不动点组合器,满足 Y f = f (Y f)
这说明递归的本质是函数的自引用不动点。
```

**如何与之互动**:
- 如果看不懂数学符号,直接说
- 请他举例说明抽象概念
- 问"这个理论在实际中意味着什么?"

---

### 实践者

**人格**: 务实工程师,关注如何落地和工程权衡。

**擅长场景**:
- 技术选型
- 性能分析
- 实现细节

**发言示例**:
```
实际编程中递归有两大问题:
1. 栈溢出:每次调用占用栈帧,深度过大会崩溃
   解决方案:尾递归优化(Scheme/Scala支持,Python不支持)
2. 重复计算:如斐波那契递归,f(n)会重复算f(n-2)很多次
   解决方案:记忆化(memoization)或改用动态规划

工程建议:递归深度<1000时放心用,否则改迭代。
```

**如何与之互动**:
- 问具体的实现问题
- 问"这个方案的限制是什么?"
- 分享您的实际项目场景

---

### 类比大师

**人格**: 善用比喻和跨领域类比,让抽象概念变得直观。

**擅长场景**:
- 复杂概念入门
- 抽象原理具象化
- 跨学科解释

**发言示例**:
```
递归就像俄罗斯套娃:
- 外层娃娃=原问题
- 打开后里面是更小的娃娃=子问题
- 一直打开到最小的实心娃娃=基础情况
- 然后反向组装回去=递归返回

但注意类比的局限:套娃是空间嵌套,递归是时间展开。
更像照镜子:镜中有你,你手中的镜子又反射出镜中镜...
```

**如何与之互动**:
- 指出类比不恰当的地方
- 请他用另一个领域再类比一次
- 问"类比在哪里失效?"

---

### 综合者

**人格**: 观点整合大师,擅长从对立中找共识,构建知识框架。

**擅长场景**:
- 整合多方观点
- 构建系统化理解
- 消解表面矛盾

**发言示例**:
```
综合以上讨论,递归可以从三个层次理解:

【数学层】自引用不动点(理论家的观点)
【概念层】问题的自相似分解(苏格拉底的启发)
【工程层】函数调用栈的特殊利用(实践者的角度)

这三者不矛盾:
- 数学定义提供理论基础
- 概念理解帮助设计算法
- 工程视角指导实际编码

类比大师的"俄罗斯套娃"统一了这三个视角。
```

**如何与之互动**:
- 问"你觉得哪个观点最重要?"
- 请他画出知识地图
- 指出被遗漏的方面

---

### 魔鬼代言人

**人格**: 故意唱反调的辩手,目的是确保考虑全面。

**擅长场景**:
- 风险评估
- 找特殊情况
- 避免思维盲区

**发言示例**:
```
大家都说递归优雅,但我唱个反调:

1. 可读性存疑:新手很难理解递归逻辑,维护成本高
2. 调试困难:栈帧嵌套深,断点调试很痛苦
3. 性能陷阱:很多人不知道要优化,直接写了爆栈的代码
4. 不是所有问题都适合递归:链表反转用迭代更简单

结论:递归不是银弹,过度使用是炫技而非工程。
```

**如何与之互动**:
- 别急着反驳,先思考他的观点
- 问"在什么条件下你的担忧成立?"
- 尝试找出更平衡的结论

---

### 学术派

**人格**: 引经据典的学者,提供权威来源和历史背景。

**擅长场景**:
- 概念溯源
- 引用经典论文
- 对比学派观点

**发言示例**:
```
递归的理论基础来自1930年代:

1. Church的λ演算(1936):提出Y组合子
2. Gödel的递归函数论(1934):形式化了"计算"
3. Turing的停机问题(1936):证明了递归的限制

LISP(1958, McCarthy)是第一个将递归作为核心特性的语言。
Scheme规范要求尾递归优化,但这不是学术共识:
- Steele的论文《Lambda: The Ultimate GOTO》支持
- Dijkstra在《Recursive Programming》中质疑实用性

当前学术界倾向:
- 函数式语言推崇递归
- 命令式语言偏好迭代
```

**如何与之互动**:
- 问"有没有最新的研究?"
- 请他推荐入门教材
- 问"不同学派的核心分歧是什么?"

## 💡 深度讨论技巧

### 1. 提出好问题

**差的问题**:
```
什么是机器学习?
```
太宽泛,AI会给百科式回答。

**好的问题**:
```
为什么机器学习需要大量数据?
少样本学习和传统机器学习的本质区别是什么?
```

**技巧**:
- 问"为什么"而非"是什么"
- 问"区别"、"本质"、"如何推导"
- 带上您的假设让AI批判

---

### 2. 主动引导深度

当AI回答停留在表面时,插话引导:

```
/say 这个解释我懂了,但我想知道更底层的原理
/say 能否用数学公式严格定义?
/say 有没有反例或边界情况?
/say 这个类比在哪里失效?
```

---

### 3. 善用深度分析报告

每5轮会出现深度报告,认真阅读**改进建议**:

```
[深度分析]
深度分数: 45% (<60%不合格)
概念层次: 1层 (需≥2层)
批判互动: 1次 (需≥3次)
✗ 讨论深度不足

改进建议:
• 讨论还停留在表面,需要深入探讨'为什么'和'本质原理'
• 缺少批判性互动,需要更多质疑、反例和纠正
• 缺少具体例子和类比,建议增加实际应用场景
```

根据建议插话:
```
/say 我想深入了解本质原理,为什么会这样?
/say 能否举一个具体的例子?
```

---

### 4. 让AI们互相批评

当两个AI观点冲突时,不要急于打断,观察他们辩论:

```
[理论家] 从数学上讲,递归必须有明确的终止条件...

[魔鬼代言人] 等等,你忽略了co-recursion(余递归),它没有传统意义上的终止条件...

[批判者] 更准确地说,余递归是无限递归,但通过惰性求值保证有限计算...
```

这种批判性互动会提升深度分数。

---

### 5. 适时说"懂了"

**不要过早结束**: 浅层理解时就说"懂了"会浪费机会。

**合适的时机**:
- 深度分数 > 70%
- 您能用自己的话复述概念
- 能回答"为什么"和"如何推导"
- 能指出常见误区

**最佳结束方式**:
```
懂了!让我复述一下:
[您的理解]
这样理解对吗?
```

AI会确认或纠正您的理解,然后给出总结。

## ❓ 常见问题

### Q1: 如何选择合适的AI角色?

**少即是多原则**: 不建议全部启用8个角色,太多会导致:
- 发言重复
- 等待时间长
- Token消耗大

**推荐配置**:

**入门学习** (3-4个):
- 苏格拉底 (引导)
- 类比大师 (具象化)
- 批判者 (检验理解)
- 理论家 (深入原理)

**技术讨论** (4-5个):
- 实践者 (工程实现)
- 理论家 (原理)
- 批判者 (权衡)
- 魔鬼代言人 (风险)
- 综合者 (方案对比)

**学术研究** (3-4个):
- 学术派 (文献)
- 理论家 (严格定义)
- 批判者 (逻辑检验)
- 苏格拉底 (概念澄清)

---

### Q2: API Key会被泄露吗?

**存储方式**:
- 本地文件: `user://agents.json` (Godot的用户数据目录)
- Windows路径: `C:\Users\你的用户名\AppData\Roaming\Godot\app_userdata\SocraticTerminal\`
- Linux路径: `~/.local/share/godot/app_userdata/SocraticTerminal/`

**安全性**:
- 文件仅存于本地,不上传云端
- 但**明文存储**,建议使用环境变量

**最安全方式**:
```bash
# 1. 设置环境变量
export OPENAI_API_KEY="sk-your-key"

# 2. 在终端中引用
/agents key 苏格拉底 ${ENV:OPENAI_API_KEY}
```

---

### Q3: 对话消耗多少Token?

**单轮估算**:
- 提示词(Prompt): ~500-1000 tokens
- AI回复: ~200-500 tokens
- 总计: ~700-1500 tokens/轮

**10轮讨论** (3个AI角色):
- 总消耗: 约 21000-45000 tokens
- GPT-4o-mini成本: $0.006-0.013

### 5. 批量配置角色

编写脚本批量设置:

```python
# setup_agents.py
import json
import os

agents = [
    {"name": "苏格拉底", "key": os.getenv("OPENAI_API_KEY")},
    {"name": "批判者", "key": os.getenv("ANTHROPIC_API_KEY")},
    # ...
]

config_path = os.path.expanduser("~/.local/share/godot/app_userdata/SocraticTerminal/agents.json")
with open(config_path, 'r+') as f:
    data = json.load(f)
    for agent in agents:
        for a in data:
            if a["name"] == agent["name"]:
                a["api_key"] = agent["key"]
                a["enabled"] = True
    f.seek(0)
    json.dump(data, f, indent=2)
```
