## 🎯 关键设计亮点

### 1. AI驱动的涌现叙事

不同于传统游戏的脚本化剧情，Microverse的故事是从AI角色的互动中自然涌现的：

```
传统RPG:
  任务: "去找Alice拿钥匙" → 固定对话 → 获得钥匙

Microverse:
  观察: Alice今天心情不好
  原因: 昨天和老板Stephen吵架了
  影响: Alice可能不愿意帮忙
  解决: 先送礼物提升好感度，或者找Stephen调解
  结果: 多种可能的结局
```

### 2. 多维度社交关系

每对角色之间有多个关系维度：

- **友谊** (0-1200): 基础好感度
- **恋爱** (0-1000): 浪漫关系
- **信任** (0-100): 是否信任对方
- **尊重** (0-100): 可以为负值
- **职场关系**: 同事/上下级
- **冲突记录**: 历史矛盾

### 3. 真实的AI决策

AI不是简单的随机行为，而是基于多因素权重决策：

```gdscript
决策因素:
- 当前时间段 (早晨/中午/傍晚)
- 精力值、饥饿度、社交需求
- 工作压力、心情
- 附近有谁
- 待办任务
- 关系状态
- 性格特质

→ 计算每个可能行动的权重
→ 加入随机性（AI不应该完全可预测）
→ 执行最优行动
```

### 4. AI驱动的自主生活循环 + 观察者控制

```
AI每日循环(完全自主):
  6:00  - AI起床，规划今日活动
  8:00  - AI角色自主前往工作场所
  12:00 - AI自主选择午餐地点和社交
  18:00 - AI下班,自主选择娱乐或社交
  22:00 - AI回家休息

AI周循环:
  周一-周五: AI按职业工作
  周六: AI自主选择参加集市或休闲
  周日: AI自由活动(可能组织聚会)

季节循环:
  春 → 夏 → 秋 → 冬 (每季28天)

观察者功能:
  - 观察者可以控制时间流速(暂停/1x/2x/5x/10x)
  - 观察者可以查看任何AI的数据和关系
  - 观察者可以创建新AI投放到世界
  - 观察者可以有限互动,但不能控制AI决策
```

## 💡 设计哲学

### "观察者"而非"主角"

玩家在Microverse中的身份是独特的：

> **"在Microverse,AI不是工具人,而是虚拟生命。**
> **玩家不是主角,而是见证者和引导者。**
> **故事不是脚本,而是涌现的奇迹。"**

**观察者的能力**:
- ✅ 观察任何AI的生活、工作、社交
- ✅ 查看AI的记忆、情绪、关系数据
- ✅ 控制时间流速(暂停/加速/快进)
- ✅ 创建新AI角色投放到世界
- ✅ 以"神秘访客"身份有限互动

**观察者不能做的**:
- ❌ 直接控制AI的决策
- ❌ 强制AI做任何事
- ❌ 预知AI的未来选择

### "涌现"而非"预设"

> "最好的故事不是写出来的，而是发生的。
> 当Alice和Joe因为共同兴趣而相恋，
> 当Tom因为性格孤僻逐渐失去朋友，
> 当Stephen的公司因为AI员工集体跳槽而困境...
> 这些都不是我们设计的剧情，而是AI自主互动的自然结果。
> 观察者只是见证这些故事的发生。"
