## 一、项目概述

### 1.1 项目定位

**Microverse In Box(盒中小世界)** 是一款创新的AI驱动社交模拟游戏,核心特点:

- **玩家角色**: 观察者/上帝视角,而非传统的主角
- **AI驱动**: 8个AI角色拥有真实思考、记忆、情感和目标
- **涌现叙事**: 故事从AI自主互动中自然产生,非预设剧本
- **时间控制**: 玩家可控制时间流速(暂停/加速/快进)
- **完整模拟**: 时间、经济、社交、职业、记忆等完整系统

### 1.2 技术栈

- **引擎**: Godot 4.5.1 (已验证兼容)
- **语言**: GDScript (Godot 4.x标准语法)
- **AI集成**: OpenAI/Claude/Gemini/DeepSeek/Doubao/Kimi/Ollama
- **数据存储**: JSON + SQLite混合方案
- **架构模式**: Autoload单例 + 信号驱动 + 组件化

## 二、核心设计理念深度理解

### 2.1 设计哲学三大核心

#### 1. AI优先 (AI-First)
> "AI不是工具人,而是虚拟生命"

**设计原则**:
- 每个AI决策都应该有意义
- AI的记忆系统是叙事的基础
- 玩家的互动应该影响AI的长期发展
- AI之间的关系是动态可演化的

**实现要点**:
- AI拥有完整的数据结构(50+字段)
- 性格基于Big Five模型(外向/友善/尽责/神经质/开放性)
- 记忆分层(工作记忆/短期记忆/长期记忆/核心记忆)
- 每30分钟游戏时间更新一次决策(LLM驱动)

#### 2. 涌现叙事 (Emergent Storytelling)
> "最好的故事不是写出来的,而是发生的"

**对比传统游戏**:
```
传统RPG:
  NPC: "我需要5个苹果,请帮我收集"
  玩家: 收集后交付
  NPC: "谢谢你!这是奖励"

Microverse涌现叙事:
  第1天: Alice抱怨工作太累,想辞职
  第5天: Tom向老板Stephen汇报
  第7天: Stephen提议给Alice加薪,但要求996
  第10天: Alice在咖啡店向Joe吐槽老板PUA
  第15天: Joe写工具送给Alice,减轻她工作
  第20天: Alice和Joe开始约会
  结局A/B/C: 多种可能的未来...
```

**实现机制**:
- AI之间的关系是双向的,有好感/信任/浪漫等多维度
- 每次互动都创建记忆,影响未来决策
- 冲突/和解/表白都是自然触发,非脚本化
- LLM根据历史记忆生成符合性格的行为

#### 3. 观察者模式 (Observer Pattern)
> "玩家不是主角,而是见证者和引导者"

**玩家可以做的**:
- ✅ 观察任何AI的记忆、情绪、关系
- ✅ 查看小镇统计数据(经济、社交、事件)
- ✅ 控制时间流速(暂停/1x/2x/5x/10x)
- ✅ 创建新AI角色投放到世界
- ✅ 以"神秘访客"身份有限对话

**玩家不能做的**:
- ❌ 直接控制AI的决策
- ❌ 强制AI做任何事
- ❌ 直接修改AI的记忆/情感/关系
- ❌ 预知AI未来的行为

### 2.2 时间系统设计精髓

**核心参数**:
```yaml
基础时间流速: ×3 (比星露谷慢,但比现实快)
时间单位: 10分钟游戏时间 = 60秒现实时间
AI更新间隔: 30分钟游戏时间
游戏一天: 20小时(6:00-26:00) = 120分钟现实(2小时)

换算:
  1游戏日 = 2小时现实
  1游戏周 = 14小时现实
  1游戏季(28天) = 56小时现实
  1游戏年(112天) = 224小时现实
```

**设计理由**:
1. **60秒现实时间** → LLM有足够时间生成高质量内容
2. **2小时现实 = 1游戏日** → 玩家可舒适观察AI完整一天
3. **30分钟游戏更新** → 平衡AI智能性与API成本
4. **可控时间流速** → 玩家可加速无聊时段,慢速观察精彩时刻

**时间段划分**:
- 6:00-8:00: 黎明(起床/早餐)
- 8:00-12:00: 上午(工作/活动)
- 12:00-14:00: 午间(午餐/社交)
- 14:00-18:00: 下午(工作)
- 18:00-20:00: 傍晚(下班/晚餐) ⚠️ 18:00为工作结束硬边界
- 20:00-24:00: 夜间(社交/娱乐)
- 24:00-2:00: 深夜(睡觉)
- 2:00-6:00: 凌晨(跳过)

### 2.3 AI任务系统核心

**四大任务域**:

1. **工作任务** (Work Tasks) - 占工作日80%
   - 来源: 职业系统(编码/设计/产品/运营等)
   - 奖励: 工资/绩效
   - 失败: 绩效下降/压力增加
   - 示例: 编码模块/修复Bug/Code Review/写文档

2. **日常任务** (Daily Tasks) - 占全天20%
   - 来源: 生理需求(饥饿/疲劳/卫生)
   - 奖励: 健康/情绪恢复
   - 失败: 健康下降/情绪低落
   - 示例: 吃饭/睡觉/洗澡/打扫

3. **社交任务** (Social Tasks) - 非工作时间
   - 来源: 关系系统/AI主动邀约
   - 奖励: 关系提升/情绪恢复
   - 失败: 关系下降/负面记忆
   - 示例: 约会/聚会/帮助朋友/送礼🎁

4. **成长任务** (Growth Tasks) - 自由时间
   - 来源: AI自主目标
   - 奖励: 技能提升/成就感
   - 失败: 无惩罚(但有遗憾)
   - 示例: 学习新技能/健身/阅读

**优先级矩阵** (紧急重要四象限):
```
紧急且重要 (Priority 1):
  - 紧急Bug修复
  - 重要会议
  - Deadline即将到的任务
  - 生理需求(饥饿>80, 疲劳>80)
  → 立即中断当前任务

重要但不紧急 (Priority 2):
  - 日常工作任务
  - 学习成长任务
  - 维护重要关系
  → 合理安排到日程中

紧急但不重要 (Priority 3):
  - 突然的社交邀请
  - 琐碎杂事
  → 可以拒绝或委托

不紧急不重要 (Priority 4):
  - 闲逛/拖延
  → 填充空余时间
```

### 2.4 关系系统多维度设计

**四维关系值**:
```yaml
熟悉度 (Familiarity): 0-100
  - 互动次数越多越高
  - 每天不互动会缓慢衰减
  - 影响对话深度

好感度 (Affection): -100~100
  - 可以为负(敌对关系)
  - 受性格匹配度影响
  - 决定是否愿意帮助

信任度 (Trust): 0-100
  - 建立慢,破坏快
  - 影响是否借钱/分享秘密
  - 冲突会降低信任

浪漫度 (Romance): 0-100
  - 解锁条件: 好感>60 + 熟悉>40
  - 影响表白成功率
  - 可能发展为恋爱/订婚/结婚
```

**关系标签** (动态更新):
- strangers(陌生人) → acquaintances(熟人) → friends(朋友) → close_friends(好友) → best_friends(挚友)
- colleagues(同事)
- enemies(敌人) ← rivals(竞争者)
- lovers(恋人) → engaged(订婚) → married(已婚)
- family(家人)

**互动记录**:
- 对话次数
- 送礼次数(A→B / B→A)
- 冲突次数
- 合作次数
- 共同事件/记忆
- 难忘时刻
- 关系趋势(最近10次变化)

### 2.5 记忆系统分层架构

**三层记忆结构**:

```yaml
工作记忆 (Working Memory):
  - 容量: 5-7条
  - 时效: 当前对话/任务期间
  - 用途: LLM上下文窗口
  - 示例: "刚才Joe说他喜欢咖啡"

短期记忆 (Short-term Memory):
  - 容量: 最近50条
  - 时效: 7天
  - 用途: 影响近期决策
  - 示例: "昨天和Alice约会很开心"

长期记忆 (Long-term Memory):
  - 容量: 200条
  - 时效: 30天
  - 用途: 性格塑造/关系基础
  - 示例: "我一直想学习AI技术"

核心记忆 (Core Memory):
  - 容量: 10-20条
  - 时效: 永久
  - 用途: 定义AI身份
  - 示例: "我是前端工程师,对技术充满热情"
```

**记忆评分系统**:
```gdscript
重要性 (Importance): 0-100
  - 影响记忆保留时长
  - LOW(<30): 7天后遗忘
  - NORMAL(30-70): 30天后遗忘
  - HIGH(70-90): 升级为长期记忆
  - CRITICAL(>90): 成为核心记忆

情感强度 (Emotional Intensity): 0-100
  - 影响记忆鲜活度
  - 高情感强度的记忆更难遗忘

时效性 (Recency): 0-1
  - 随时间衰减
  - 每天 ×0.95

访问次数 (Access Count):
  - 被回忆越多,越不易遗忘
  - 每次访问 strength +0.1
```

**记忆衰减机制**:
```gdscript
strength(t) = initial_strength × (1 - decay_rate × days_passed)

if strength < 0.1:
  is_forgotten = true
```

### 3.2 信号驱动架构

**EventBus核心信号**:
```gdscript
// 时间系统信号
time_tick(game_minutes_passed)
hour_changed(hour)
day_changed(year, season, day)
season_changed(season)
year_changed(year)

// AI系统信号
ai_thought_generated(ai_id, thought)
ai_action_taken(ai_id, action)
ai_dialogue_started(ai_id, target_id)
ai_dialogue_ended(ai_id)
ai_emotion_changed(ai_id, emotion)
ai_relationship_changed(ai_id, target_id, relationship)

// 职业系统信号
work_started(ai_id)
work_ended(ai_id)              # 18:00触发,决定是否加班
salary_paid(ai_id, amount)
career_promoted(ai_id, new_level)
performance_evaluated(ai_id, performance)

// 任务系统信号
task_created(ai_id, task_id)
task_started(ai_id, task_id)
task_completed(ai_id, task_id, result)
task_failed(ai_id, task_id, reason)
social_invitation_sent(inviter_id, invitee_id, task)

// 天气系统信号
weather_changed(new_weather, old_weather)
extreme_weather_event(event_type)

// 冲突系统信号
conflict_triggered(conflict_id, involved_characters)
conflict_escalated(conflict_id, new_severity)
conflict_resolved(conflict_id, resolution_type)

// 导航系统信号
location_registered(location_id)
location_occupant_changed(location_id, occupants_count)
character_arrived_at_location(ai_id, location_id)

// 存档系统信号
save_started()
save_progress_updated(progress, step)
save_completed(success, save_name)
load_completed(success, save_name)
```

**信号流向示例** (完整AI日常行为):
```
1. 时间系统触发新的一天
   TimeSystem.day_changed → TaskSystem

2. 任务系统生成今日任务
   TaskSystem.generate_daily_tasks(ai)
   - 生成工作任务 (基于CareerSystem)
   - 生成日常任务 (吃饭/睡觉)
   - 检查社交邀请

3. 天气系统影响任务
   WeatherSystem.weather_changed → TaskSystem
   - 大雨取消户外任务
   - 晴天增加户外活动

4. AI执行任务
   TaskExecutor.execute_task(task)
   - AIMovementController移动到任务地点
   - LocationManager更新地点占用
   - 执行任务逻辑

5. 任务完成评估
   TaskSystem.complete_task(ai, task)
   - LLM评估任务质量 (复杂任务)
   - 更新绩效分数 (EconomyManager)
   - 创建任务记忆 (MemoryManager)

6. 可能触发冲突
   如果任务失败或与他人产生矛盾:
   TaskSystem.task_failed → ConflictSystem
   - ConflictSystem计算冲突概率
   - 可能触发冲突
   - ConflictHandler决定应对方式

7. 关系系统更新
   ConflictSystem → RelationshipManager
   - 冲突降低关系
   - 或和解提升关系

8. 存档系统持久化
   SaveManager自动存档 (每天)
   - 收集所有系统数据
   - 序列化为JSON
   - 创建截图和备份
```

## 五、核心技术难点分析

### 5.1 LLM集成挑战

**问题1: API成本控制**
```yaml
挑战:
  - 8个AI × 每30分钟更新 × 每天20小时 = 320次/天
  - 如果每次都调用LLM → $3-5/天 (不可接受)

解决方案:
  1. 任务评估分级:
     - 简单任务(difficulty<=LOW): 规则判定, $0
     - 中等任务(MEDIUM): 50%概率LLM, $0.0005/次
     - 复杂任务(HIGH): 100%LLM, $0.001/次

  2. 使用小模型:
     - 任务评估: GPT-4o-mini
     - 简单对话: Claude-haiku
     - 复杂思考: GPT-4o

  3. Prompt优化:
     - 精简上下文 (只包含最近3条记忆)
     - 结构化输出 (JSON格式)
     - 缓存常用Prompt

  预估成本: ~$0.5-1/天 (可接受)
```

**问题2: LLM响应时间**
```yaml
挑战:
  - GPT-4o-mini平均响应: 2-5秒
  - 如果同步调用 → 游戏卡顿

解决方案:
  1. 异步调用:
     var response = await APIManager.call_llm_async(...)

  2. 请求队列:
     - 最多同时3个LLM请求
     - 超过则排队等待

  3. 预加载:
     - 提前5分钟生成下一步决策
     - 存储在ai.pending_decision

  4. 降级策略:
     - 超时10秒 → 使用规则决策
     - 失败3次 → 使用上次决策模板
```

**问题3: LLM输出解析**
```yaml
挑战:
  - LLM输出不稳定 (格式错误/拒绝输出/幻觉)

解决方案:
  1. 强制JSON格式:
     - Prompt明确要求: "请以JSON格式输出: {...}"
     - 使用JSON.parse_string()解析
     - 提取JSON代码块: ```json...```

  2. 验证输出:
     func _validate_llm_output(response: Dictionary) -> bool:
       if not response.has("decision"):
         return false
       if response.decision not in VALID_ACTIONS:
         return false
       return true

  3. 默认值兜底:
     var decision = response.get("decision", "idle")
     var reason = response.get("reason", "正常行为")
```

### 5.2 性能优化挑战

**问题1: 8个AI同时运行**
```yaml
挑战:
  - 每个AI每帧更新 (60fps) → 480次/秒
  - 每个AI有50+字段 → 大量内存访问

解决方案:
  1. 降低更新频率:
     - AI不是每帧更新，而是每30游戏分钟
     - 60秒现实 = 1次更新

  2. 可见性剔除:
     if not character.is_visible_in_tree():
       ai_brain.reduce_update_frequency()
       animation_controller.pause()

  3. 批量处理:
     # 不要这样:
     for ai in ais:
       ai.update()
       await ai.think()  # 串行

     # 应该这样:
     var tasks = []
     for ai in ais:
       tasks.append(ai.think_async())  # 并行
     await Promise.all(tasks)
```

**问题2: SQLite查询性能**
```yaml
挑战:
  - 记忆查询: "获取AI最近50条记忆"
  - 如果数据库有10万条记忆 → 全表扫描

解决方案:
  1. 索引优化:
     CREATE INDEX idx_ai_id ON memories (ai_id)
     CREATE INDEX idx_created_at ON memories (created_at)
     CREATE INDEX idx_importance ON memories (importance)

  2. 分页查询:
     SELECT * FROM memories
     WHERE ai_id = ?
     ORDER BY created_at DESC
     LIMIT 50

  3. 内存缓存:
     var _memory_cache: Dictionary = {}  # {ai_id: [memories]}

     func get_recent_memories(ai_id):
       if _memory_cache.has(ai_id):
         return _memory_cache[ai_id]

       var memories = _query_database(ai_id)
       _memory_cache[ai_id] = memories
       return memories

  4. 定期清理:
     # 每周删除遗忘的记忆
     DELETE FROM memories WHERE is_forgotten = 1
```

**问题3: UI更新卡顿**
```yaml
挑战:
  - ObservationUI显示关系图谱 (8×8=64个节点)
  - 每秒刷新 → 绘制64条连线 → 卡顿

解决方案:
  1. 更新节流:
     var _last_ui_update_time: float = 0.0
     const UI_UPDATE_INTERVAL: float = 0.5  # 每0.5秒

     func _process(delta):
       _last_ui_update_time += delta
       if _last_ui_update_time >= UI_UPDATE_INTERVAL:
         _update_ui()
         _last_ui_update_time = 0.0

  2. 增量更新:
     # 不要每次重绘所有节点
     func _on_relationship_changed(ai_a, ai_b, rel):
       _update_single_edge(ai_a, ai_b)  # 只更新这条边

  3. LOD系统:
     # 当关系图很复杂时,隐藏弱关系
     if relationship.affection < 20:
       edge.visible = false
```

### 5.3 数据一致性挑战

**问题1: 时间同步**
```yaml
挑战:
  - TimeSystem推进时间
  - TaskSystem需要知道时间变化
  - ScheduleManager也需要知道
  → 如果不同步,任务可能永远不执行

解决方案:
  # TimeSystem
  func _advance_time(minutes: float):
    # ... 更新时间
    EventBus.emit_signal("time_tick", minutes)
    if hour_changed:
      EventBus.emit_signal("hour_changed", current_hour)

  # TaskSystem
  func _ready():
    EventBus.connect("hour_changed", _on_hour_changed)

  func _on_hour_changed(new_hour: int):
    for ai_id in active_tasks:
      _check_pending_tasks(ai_id, new_hour)
```

**问题2: 关系双向同步**
```yaml
挑战:
  - Alice对Joe的好感: 80
  - Joe对Alice的好感: 60
  → 两个方向的关系需要分别维护

解决方案:
  # RelationshipManager
  var _relationships: Dictionary = {}  # {ai_a: {ai_b: RelData}}

  func update_relationship(ai_a, ai_b, dimension, change):
    # 只更新单向关系
    if not _relationships.has(ai_a):
      _relationships[ai_a] = {}

    _relationships[ai_a][ai_b][dimension] += change

    # 不要自动更新反向关系!
    # Joe对Alice的好感变化应该由Joe的决策触发
```

**问题3: 存档版本兼容**
```yaml
挑战:
  - v1.0存档: {"ai_characters": [...]}
  - v1.1新增: {"ai_characters": [...], "weather_state": {...}}
  → 旧存档无法加载

解决方案:
  # SaveManager.gd
  const CURRENT_SAVE_VERSION = "1.1"

  func load_game(save_path):
    var save_data = _read_json(save_path)
    var version = save_data.get("game_version", "1.0")

    # 版本迁移
    save_data = _migrate_save_data(save_data, version)

    _apply_save_data(save_data)

  func _migrate_save_data(data, from_version):
    if from_version == "1.0":
      # 1.0 → 1.1: 添加天气状态
      data["weather_state"] = {
        "current_weather": "sunny",
        "intensity": 1.0
      }
      from_version = "1.1"

    if from_version == "1.1":
      # 1.1 → 1.2: 添加冲突历史
      data["conflict_history"] = []
      from_version = "1.2"

    return data
```

## 七、开发建议与注意事项

### 7.1 开发顺序建议

**严格按照Phase A→B→C→D→E顺序**:

```yaml
为什么不能跳跃:
  ❌ 不能先做TaskSystem再做TimeSystem
     → TaskSystem依赖TimeSystem的hour_changed信号

  ❌ 不能先做EconomyManager再做TaskSystem
     → EconomyManager的工资计算依赖TaskSystem的get_weekly_performance()

  ❌ 不能先做UI再做后端系统
     → ObservationUI需要从RelationshipManager查询数据

正确顺序:
  1. TimeSystem → 2. EventBus → 3. ConfigManager
  4. CareerSystem → 5. ScheduleManager → 6. TaskSystem
  7. EconomyManager → 8. RelationshipManager
  ...
```

### 7.3 测试策略

**单元测试 (GUT框架)**:
```gdscript
# tests/unit/test_time_system.gd
extends GutTest

var time_system: TimeSystem

func before_each():
    time_system = TimeSystem.new()
    add_child_autofree(time_system)

func test_time_advance():
    # 测试时间推进是否正确
    time_system.current_hour = 8.0
    time_system._advance_time(60)  # 推进60分钟

    assert_eq(time_system.current_day, 2, "天数应该增加")

func test_season_change():
    # 测试季节切换
    time_system.current_season = "Spring"
    time_system.current_day = 28
    time_system._advance_time(24 * 60)  # 推进1天

    assert_eq(time_system.current_season, "Summer", "春季28天后应该是夏季")
    assert_eq(time_system.current_day, 1, "新季节第1天")

# script/debug/DebugConsole.gd
func _update_performance_stats():
    var stats = """
[性能监控]
FPS: %d
内存: %.1f MB
LLM调用/分钟: %d
活跃AI: %d
活跃任务: %d
数据库大小: %.1f MB
    """ % [

        APIManager.get_calls_per_minute(),
        CharacterManager.get_active_ai_count(),
        TaskSystem.get_active_task_count(),
        _get_database_size()
    ]

    performance_label.text = stats

func _get_database_size() -> float:
    var db_path = "user://microverse_data.db"
    if FileAccess.file_exists(db_path):
        var file = FileAccess.open(db_path, FileAccess.READ)
        var size = file.get_length()
        file.close()
        return size / 1024.0 / 1024.0
    return 0.0
```
